Overview — Three Election Types

VeriVote Kenya is not a single-purpose system. It is a sovereign cryptographic voting platform capable of running three fundamentally different categories of election, each with its own registration model, declaration hierarchy, and access control — all sharing the same encrypted vote counting engine.

🏛️ Government
  • IEBC-administered
  • National ID + KYC
  • Geographic jurisdiction
  • 9 Commissioners declare
  • Constitutional timelines
🎓 Institutional
  • Organisation-administered
  • Member roster registration
  • Role-based access
  • Council/RO declares
  • Custom election cycles
🏢 Corporate
  • Company-administered
  • Shareholder register
  • Weighted voting
  • Company Secretary declares
  • AGM/EGM schedules

All three types use the same ElGamal homomorphic encryption, the same re-encryption mixnet, and the same Shamir's Secret Sharing key ceremony for vote counting. The difference lies in who registers, how they authenticate, and who has the authority to declare results.

A Government Election Journey IEBC · Kenya General Election

🏛️
Kenya General Election 2027
Example: Wanjiku Kamau, registered voter, Westlands Constituency, Nairobi County.
She will vote for: President, Governor, Senator, Women Rep, MP (Westlands), MCA (Parklands/Highridge ward).
Phase 1 — Voter Registration
1
Identity Verification (KYC via Persona)
Wanjiku visits a polling station or registers online. She submits her National ID number 24681357. The system forwards this to Persona — a live identity verification service that cross-checks her ID, takes a photo, and runs a liveness test (she must blink on camera). This takes about 90 seconds.
2
Wallet Creation + Soul-Bound Token (SBT) Minting
Once Persona approves, the system generates a blockchain wallet address for Wanjiku and mints a Soul-Bound Token — a non-transferable NFT recorded permanently on the chain. Her sbtTokenId, sbtAddress, and blockchain transaction hash are stored in the database.
3
Normal PIN Setup
Wanjiku chooses a 4-digit voting PIN (e.g. 7842) — like her bank ATM PIN, but for voting. The system hashes it with argon2id (a deliberately slow algorithm designed to make brute-force cracking impractical) and stores only the hash. The actual digits are never stored anywhere.
4
Distress PIN Delivery
The server generates a different 4-digit PIN — the Distress PIN — and sends it privately to Wanjiku's phone via SMS. This PIN is never shown on-screen. Only Wanjiku and the SMS have it. It is also stored as an argon2id hash only.
5
Optional: WebAuthn Biometric Enrolment
Wanjiku can optionally register her fingerprint or Face ID on her smartphone. The device's secure chip signs a challenge from the server — her biometric never leaves her phone. Future logins can use fingerprint instead of PIN.
Analogy — The Voter Registration Card That Cannot Be Stolen The Soul-Bound Token is like a voter registration card tattooed to Wanjiku's identity. In the physical world, someone could steal her card and impersonate her. With the SBT, it is mathematically bound to her wallet — transferring it to another address is impossible by design. The blockchain independently proves she is a legitimate registered voter even if the entire VeriVote database were deleted.
The Distress PIN — Silent Duress Alerting If someone forces Wanjiku at gunpoint to vote for a particular candidate, she enters her Distress PIN instead of her normal PIN. Her vote is cast normally — the attacker sees it succeed and walks away. Behind the scenes, the vote is silently flagged isDistressFlagged = true, IEBC security is alerted, and the vote can be reviewed or nullified. The attacker never knows. This mirrors the duress codes used in high-security bank vaults.
Phase 2 — Election Day Voting
6
Authentication → JWT Issued
On election day, Wanjiku visits verivote.ke/vote on any device. She enters her National ID and PIN. The server runs argon2id on her submitted PIN and compares the hash — if it matches, a JSON Web Token (JWT) is issued. This token is valid for 24 hours and is signed with the server's secret key so it cannot be forged.
7
Jurisdiction-Filtered Ballot Loaded
The system looks up Wanjiku's pollingStationId → ward → constituency → county and returns only the races relevant to her: Presidential (national), Gubernatorial (Nairobi), Senator (Nairobi), Women Rep (Nairobi), MP (Westlands), MCA (Parklands/Highridge). A voter in Kisumu sees different candidates entirely.
8
Vote Encryption (ElGamal) — Before Leaving the Browser
Wanjiku selects her candidates and clicks "Submit." Before the data is sent, each vote selection is encrypted using the election's public key. The server never sees plaintext votes. It receives only ciphertexts — mathematical objects that look like random numbers.
9
PIN Verified + Vote Stored + Blockchain Anchored
The server: (1) verifies the PIN hash, (2) confirms Wanjiku's SBT is valid on-chain, (3) checks she hasn't already voted, (4) stores the ciphertext in the votes table, (5) submits the vote's SHA-256 hash to the Ethereum chain. The blockchain transaction produces a txHash — a public, immutable record.
10
Vote Receipt Issued
Wanjiku receives a 16-character serial number, e.g. VV-2027-XK9M2L. She can later visit /verify/VV-2027-XK9M2L to confirm her vote was received, the hash is valid, and the blockchain confirms it — all without revealing which candidates she chose.
Analogy — The JWT as a Concert Wristband When Wanjiku enters her PIN, the system is like a concert gate — it verifies her identity once, thoroughly, and then gives her a wristband (the JWT). For the rest of the day she shows the wristband at every door, not her ID. The wristband has an expiry time and a cryptographic signature. A fake wristband — even a perfect physical copy — is immediately detected because it lacks the correct signature.
How ElGamal Encryption Works The election has a public key g^x mod p where x is the private key locked away until the counting ceremony. To encrypt a vote for Candidate A (encoded as 1):

Ciphertext = (g^r, g¹ · (g^x)^r) where r is a fresh random number per vote.

Even two identical votes for the same candidate look completely different because r is different each time. An observer cannot tell who voted for whom — not even by comparing ciphertexts.
Phase 3 — The Counting Ceremony
11
Re-Encryption Mixnet (3 Nodes)
All encrypted votes pass through a 3-node re-encryption mixnet. Each node takes the batch, wraps every vote in a fresh layer of encryption (changing its appearance completely), shuffles the order randomly, and passes it to the next node. The output is a randomly ordered batch with no link to the input order.
12
Homomorphic Aggregation
The 1,000+ anonymised ciphertexts are mathematically multiplied together while still encrypted. Due to ElGamal's homomorphic property, multiplying ciphertexts is equivalent to adding the underlying votes. This collapses millions of ciphertexts down to one ciphertext per candidate, containing the total votes for that candidate — still encrypted.
13
Shamir's Secret Sharing — Key Split
The ElGamal private key x is split into 3 shares using a degree-2 polynomial. Commissioner Amos gets Share 1, Commissioner Beatrice gets Share 2, Commissioner Chege gets Share 3. No single commissioner — nor any two of them — can reconstruct the key alone. All three shares are needed.
14
Physical Share Entry by All 3 Commissioners
Each commissioner physically types their hex share code into the system. The portal shows a Pedersen commitment next to each share code — a public fingerprint that confirms the share is genuine without revealing its value. Observers can verify commitments without seeing the secret.
15
Lagrange Reconstruction + Tamper Check
Once all 3 shares are entered, the system reconstructs the private key using closed-form Lagrange interpolation: x = 3·f(1) − 3·f(2) + f(3) (mod p). Before using the key, it verifies: g^x_reconstructed = publicKey. If this check fails, at least one share is corrupted — the ceremony halts immediately.
16
Decryption + Baby-Step Giant-Step (BSGS)
The aggregated ciphertext for each candidate is decrypted. The result is g^total — not total directly. The system uses BSGS to recover the actual vote count: instead of checking all possibilities up to N, it precomputes √N values and finds the answer in √N lookups — 1,000× faster than brute force for 1,000,000 votes.
17
Integrity Hash Published
A final SHA-256 integrity hash is computed over the mixnet commitment and the tally hash: SHA-256(mixnetCommitment | tallyHash). This hash is published publicly. Tampering with any part of the process — even a single bit — produces a completely different hash, immediately detectable by any observer.
Analogy — The Mixnet as Three Postal Trustees Imagine 1,000 sealed envelopes arrive at a sorting centre. Before counting, three independent trustees each take the pile, re-seal every envelope in a fresh outer envelope (re-encryption), shuffle the pile randomly, and hand it to the next trustee. After all three trustees are done, nobody — including the trustees working together — can match any output envelope to its original sender. The votes are anonymised by position, not just by encryption.
Analogy — Homomorphic Encryption as a Magic Adding Machine Imagine a machine that can add numbers together while they're inside locked boxes. You feed in 1,000 locked boxes, and it outputs a single locked box containing their sum — without opening any box. After aggregation, there is one encrypted box per candidate. Only during the key ceremony is that final box opened to reveal the total. Not a single individual vote was decrypted at any point.
Analogy — Shamir's Secret Sharing as Nuclear Launch Codes In nuclear deterrence, no single person can launch a missile. Multiple officers must simultaneously insert their keys. Shamir's Secret Sharing applies this to the election private key. Commissioner Amos, Beatrice, and Chege each hold one piece. Amos and Beatrice together cannot decrypt anything — they are still one share short. Only when all three enter their codes does the system reconstruct the decryption key.
Phase 4 — Results Declaration
18
Jurisdiction-Scoped Declarations
Results are declared by different officials depending on the position scope. Each declaration is a formal legal act recorded in the system with a timestamp.

Each declaration moves through: DRAFT → DECLARED. An IEBC Commissioner can challenge any declaration (CONTESTED). Contested results trigger a review and can be ANNULLED. The VeriVote system mirrors Kenya's Elections Act requirements exactly.

Blockchain Audit Trail — The Glass Ballot Box In Kenya's physical elections, ballot boxes are transparent so voters, candidates, and agents can all observe. VeriVote is the digital equivalent: every vote has a blockchain transaction hash, every mixnet node publishes a commitment, every tally has a hash, and an integrity hash ties all phases together. Anyone — anywhere in the world — can verify the election was conducted honestly without being able to identify any individual voter.

B Institutional Election Journey Law Society of Kenya · Council Elections

🎓
Law Society of Kenya — Council Elections 2027
Example: Advocate Brian Otieno, Nairobi Branch member, voting for LSK Council representatives.
Positions: National Council (all members vote) · Nairobi Branch Chair · Nairobi Branch Council (up to 5 selections).
Key Difference from Government Elections In a government election, the public registers themselves through KYC. In an institutional election, the organisation already knows its members — they are advocates on the Roll of Advocates, or university students enrolled in the registry, or SACCO members on the membership roll. There is no Persona KYC. The institution's administrator registers members directly into VeriVote using existing records.
Phase 1 — Member Registration (Admin-Managed)
1
LSK Creates the Election
The LSK ICT Admin logs into the VeriVote admin portal, creates a new election of type INSTITUTIONAL, sets the election name "LSK Council Elections 2027", adds positions (National Council, Nairobi Branch Chair, Nairobi Branch Council), and assigns candidates to each position.
2
Bulk Member Import
The ICT Admin imports the current Roll of Advocates from LSK's membership database. Each advocate is registered with their Advocate Admission Number (used instead of National ID) as their unique identifier. No Persona KYC — LSK already verified their identity when they were admitted to the bar.
3
Credentials Sent to Members
Each registered advocate receives an email with their login credentials and a link to set their voting PIN. Because there is no KYC step, the setup is faster: Advocate Number → PIN setup → done. No biometric photo, no document scan.
Phase 2 — Voting (Identical Cryptography)
4
Brian Authenticates
Brian visits the LSK election portal, enters his Advocate Number and PIN. A JWT is issued. His ballot is loaded — filtered to show positions relevant to Nairobi Branch members (he sees Nairobi Branch Chair and Council in addition to the national positions). A member from Coast Branch would see different regional positions.
5
Vote Encrypted, Stored, Anchored
Identical to the government flow: Brian's selections are ElGamal-encrypted in the browser before submission. The server verifies his PIN, stores the ciphertext, and records the blockchain transaction hash. His serial number receipt works the same way.
Analogy — The Difference Between Public and Private Registration A government election is like a national census — anyone who is a citizen qualifies, and they prove it by showing their ID at a verification office. An institutional election is like a members-only club AGM — you don't need to prove you're a citizen, you need to prove you're a member. The club already has the membership roll. VeriVote accepts both models: when the institution provides the roll, no external KYC is needed.
Phase 3 — Counting (Same Ceremony, Different Commissioners)
6
LSK Assigns Its Own Commissioners
For the key ceremony, LSK designates three senior advocates as "commissioners" in the VeriVote staff system. They each receive an SSS share when the ceremony starts. The cryptographic ceremony is identical to a government election — three share-holders, Lagrange reconstruction, homomorphic tally, BSGS. The only difference is who the humans are.
7
Results Declared by LSK Returning Officer
The LSK CEO (or appointed Returning Officer) formally declares each result in the system. For national positions: National RO declares. For Nairobi Branch: Nairobi Branch RO declares. The declaration hierarchy mirrors LSK's constitution, not IEBC's jurisdiction map.

C Corporate Election Journey Safaricom PLC · Annual General Meeting

🏢
Safaricom PLC — Annual General Meeting 2027
Example: Investor Amina Hassan, holding 150,000 Safaricom shares, voting on board appointments and resolutions.
Resolutions: Director appointments (3 seats) · Auditor reappointment · Dividend approval · Share buyback programme.
Corporate Election — What Is Different Corporate elections have two features not present in government or institutional elections:

1. Weighted voting: Amina's 150,000 shares give her 150,000 votes. A small retail investor with 100 shares gets 100 votes. This is "one share, one vote" rather than "one person, one vote."

2. Resolution-based ballot: Instead of choosing between candidates, shareholders vote FOR or AGAINST specific resolutions. The "candidates" are the resolutions themselves.
Phase 1 — Shareholder Registration
1
Company Secretary Creates the AGM
Safaricom's Company Secretary creates a new election of type CORPORATE in VeriVote. She adds the AGM resolutions as "positions" and the options (FOR / AGAINST / ABSTAIN) as "candidates" for each resolution. She sets the voting window to match the AGM date and time.
2
Shareholder Register Import
The Share Register (maintained by the Central Depository and Settlement Corporation — CDSC) is imported. Each shareholder is registered with their CDS Account Number and their shareholding as at the record date. Amina's account shows 150,000 shares.
3
Vote Weight Encoded at Registration
When Amina is registered, her voting weight (150,000) is stored against her account. When she votes FOR a resolution, her vote is encoded as 150,000 instead of 1. The ElGamal encryption and homomorphic aggregation handle weighted votes identically to unweighted votes — the arithmetic works the same whether the numbers are small or large.
Phase 2 — AGM Day Voting
4
Amina Authenticates via Email Link
Amina receives a secure login link at her registered email. She clicks it, sets a voting PIN, and is presented with her personalised ballot. Each resolution is listed: "Appointment of Mr X as Director — FOR / AGAINST / ABSTAIN." Her ballot header shows: "You are voting as holder of 150,000 ordinary shares."
5
Weighted Vote Encrypted and Submitted
When Amina votes FOR Resolution 1, the system encodes her vote as g^150000 in the ElGamal ciphertext. For a retail investor with 100 shares, it would be g^100. After homomorphic aggregation across all shareholders, the total FOR vote on Resolution 1 is g^(sum_of_all_weights_who_voted_FOR) — the weighted total, still encrypted.
Analogy — The Difference Between One-Person-One-Vote and Shareholder Voting In a government election, every citizen's vote is equal — like one token per person at a town hall. In a corporate AGM, it is more like a partnership decision where each partner's influence is proportional to their stake. A partner who owns 40% of the firm should have 40% of the votes on major decisions. Amina's 150,000 shares in Safaricom give her exactly 150,000 tokens. The encrypted tally counts the weighted tokens, not just the number of people who said yes.
Phase 3 — AGM Counting Ceremony
6
Three Key-Holders: Company Secretary + Two Independent Directors
For corporate governance, the three SSS share-holders are typically: the Company Secretary, an Independent Non-Executive Director, and the External Auditor (e.g. KPMG partner). This mirrors the physical AGM process where the Company Secretary, a Director, and the Auditor jointly sign off on results.
7
BSGS Recovers Weighted Totals
The BSGS algorithm recovers the actual FOR / AGAINST / ABSTAIN totals per resolution, in share-weighted form. Resolution 1 result: "FOR: 1,247,893,000 shares (73.2%) / AGAINST: 441,200,000 (25.9%) / ABSTAIN: 14,000,000 (0.9%) — RESOLUTION PASSED."
8
Company Secretary Formally Declares via VeriVote
The Company Secretary formally declares each resolution in the VeriVote declarations module. The declaration includes a tally snapshot (the weighted results) and a timestamp. Passed resolutions are immediately effective. NSE and CMA filings can be generated directly from the declaration record.

D Cryptographic Deep Dives Technical Reference

① ElGamal Homomorphic Encryption

VeriVote uses Exponential ElGamal over a 2048-bit FFDHE group. The system has a fixed public key g^x mod p where x is the private key only revealed during the ceremony.

// Encrypting a vote for Candidate A (value = 1)
r = random()             // fresh random blinding factor, per vote
c1 = g^r mod p           // "envelope seal" — proves who locked it
c2 = g^vote · (g^x)^r    // "vote inside" — locked with public key

Ciphertext = (c1, c2)    // what the server receives and stores
// Homomorphic property — adding ciphertexts adds underlying votes
Enc(1) × Enc(1) = Enc(2)   // two votes for same candidate = ciphertext for 2
Enc(1) × Enc(0) = Enc(1)   // one vote + one abstain = ciphertext for 1

After aggregating all N votes:
  Enc(total_A) = Enc(v₁) × Enc(v₂) × ... × Enc(vₙ)   // one multiplication per vote

② Shamir's Secret Sharing (3-of-3)

The private key x is split using a degree-2 polynomial evaluated at three points:

// Key splitting — happens at ceremony start
f(t) = x + a₁·t + a₂·t²     // degree-2 polynomial, x is the secret

Share 1 (Amos):    f(1) = x + a₁ + a₂
Share 2 (Beatrice): f(2) = x + 2a₁ + 4a₂
Share 3 (Chege):   f(3) = x + 3a₁ + 9a₂

a₁, a₂ are random — unknown to all commissioners
// Key reconstruction — Lagrange interpolation (closed-form for 3-of-3)
x = 3·f(1) - 3·f(2) + f(3)  (mod p)

Proof:
  3(x + a₁ + a₂) - 3(x + 2a₁ + 4a₂) + (x + 3a₁ + 9a₂)
= 3x + 3a₁ + 3a₂ - 3x - 6a₁ - 12a₂ + x + 3a₁ + 9a₂
= x  ✓    (all a-terms cancel)
// Tamper verification — before using the reconstructed key
if g^x_reconstructed ≠ publicKey:
    HALT — "One or more shares are invalid. Ceremony aborted."

Only if g^x_reconstructed === publicKey does decryption proceed.

③ Baby-Step Giant-Step (BSGS) Discrete Log

After decryption, the result is g^total. Recovering total from this is the discrete logarithm problem. BSGS solves it in O(√N) time and space instead of O(N):

// BSGS — recovering vote total from g^total
Let m = ceil(√N)   // e.g. m = 1000 for up to 1,000,000 votes

Baby step:  precompute table T = { g^j : j = 0..m }   // 1000 entries

Giant step: for k = 0..m:
    check if (g^total / g^(k·m)) is in T
    if yes: total = k·m + j             // found in at most 2000 lookups

vs brute force: would check 1,000,000 values one by one

④ Re-Encryption Mixnet (Jakobsson-Juels)

// Re-encryption — changing a ciphertext's appearance without changing its value
Original:     (c1, c2) = (g^r, g^vote · (g^x)^r)

Re-encrypted: (c1·g^r', c2·(g^x)^r')   // add fresh random r' per ciphertext
            = (g^(r+r'), g^vote · (g^x)^(r+r'))

Same vote, completely different ciphertext — impossible to link input to output.

Three nodes each run this independently, shuffling the batch after re-encryption. Node commitments (SHA-256 hashes of each transformation) are published, allowing offline verification that no votes were added or removed — only reordered and re-blinded.

Result manipulation Change tally after decryption Integrity hash ties mixnet + tally — any change detectable
Single point of key compromise One insider steals the private key SSS — key never exists in one place; 3 commissioners required simultaneously
Voter privacy breach Correlate votes to voters by submission order 3-node mixnet destroys order correlation before counting
Foreign API interception Data exfiltration via cloud dependencies Fully sovereign — all cryptographic operations on-premise, zero foreign API calls during counting

Token forgery Create a fake JWT to access protected routes JWT signed with HS256 server secret; signature verified on every request
